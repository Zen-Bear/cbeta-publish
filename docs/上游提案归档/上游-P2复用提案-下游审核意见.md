## 2 事实修正

- **原 §5 修正**：现行 P0 语义是「自制/重制都读库；重制对跳过项仍重生成但不校验」。
  原文"regen_all/强制重验不读库（语义不变）"与现状不符。按现行语义验收：
  - 复用命中 → 跳过校验（`regen_all` 时仍重生成产物）；
  - 未命中 → 行为与现状一致。
- **原 §2/§3.1 修正**：实况为 `config.user.json` 已 `maxDiff=5`、`verify_root=repo/verify`；
  A5 预设 `maxDiff=10`。按 §1 统一 0 后，报告根仍按生效 `source.verify_root`。
- **原 §3.2.2 修正**：报告根**不写死** `{xml2pdf.path}/verify`；publish 解析生效预设
  `source.verify_root`（可显式覆盖 `xml2pdf.verify_reports_dir`），解析不到则关闭导入。
- **原 §4 优先级**：同意"高"。

## 3 验收档（publish 侧新增，上游无需改 verdict 逻辑）

上游按 `max_diff=0` 出严格 verdict；publish 在导入/记录时加两档自动接受：

| 档 | 条件 | 处理 |
|---|---|---|
| strict | `missing==0 且 extra==0` | 自动入库 + 记库 |
| notes | `(missing+extra) ≤ 10` 且 `diff_scope=="notes_only"` | 自动入库（标注"仅注释差异"）+ 记库 |
| 其余 | 正文差异 / >10 / scope 非 `notes_only` / 数未知 / `undetermined` | 人工检验；**放行不记库** |

- 因此上游 `verdict=fail` 且 `diff_scope=notes_only` 的报告**也会被 publish 接受**：
  请确保 fail 时也照写 `diff_scope`（现实现已具备）。
- 覆盖关系：先按档位得接受集，再做 `docx→pdf` 覆盖提升。

## 4 多源（TX0011 式）——采纳逐源

- 上游报告指纹是**逐 XML**（`xml_files=[xml_fn]`）；publish 的旧聚合指纹不匹配。
- publish 改为**逐源记录**（`verify_records` schema 2）：
  `entries[work][fmt].sources = {xml 基名: {fingerprint, verified_at, product}}`，
  全部源逐源命中才算新鲜。
- 上游无需改：一源一 `（验证）/report.json` 现状即可；匹配用 `inputs.xml_files` 基名。

## 6 再审核（2026-10-07，回应上游 §9.6 实测）

### 6.1 多源口径——选定 ②（输入集模型）

- publish 记录改为「输入集」模型：
  `entries[work][fmt].sets = [{fingerprint, inputs:[源基名…], accept, product}]`；
  新鲜＝存在一个 set 其 `inputs` 恰为**当前全部源**且指纹逐字命中。
- GUI 聚合报告天然满足（`inputs`＝全部源）；CLI 单源报告在单源 work 上等价；
  CLI 多源报告不导入（publish managed 运行的结论本来当场记录，无损失）。
- **上游无需改 GUI 报告结构**；P2 提案 §9.5 第 5 条按此关闭（无需上游实施）。

### 6.2 presets 入参——答复（白话）

- 现象：两边对"同一份配置"算指纹，现在看的是**配置从哪个文件来**（裸预设 vs run.json），
  不是**配置最终长什么样** → 同一个预设两边指纹不同，复用永不命中。
- 上游实测补充：光加 `presets=` 口子不够——`_strip_no_from`/`_theme_css_digest`/
  `_canon_annotations` 三处仍按 `config_path` 取配置。
- 我方答复：
  1. **接受**上游实现要求：`presets` 给定时三项一并由 presets 派生（传了 `presets`
     就不再理 `config_path`）；`annotations` 相对路径 publish 传入前**绝对化**。
  2. **首选**：裸预设路径提升为**出厂深合并**口径（或公开"取最终生效配置"的下游 API）——
     publish 现有裸预设调用点直接收敛，不必自包 run 包装。
  3. 若 2 不便：验收改为「三形态传入同一 effective 配置」；publish 用 run 包装取 dict
     再传 `presets=`（多一层，可行）。
- `build_report_json` 透传 `presets=`：同意。
