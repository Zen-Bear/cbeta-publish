# 批量合并（含 ZIP）与官方书刷新 — 设计与实施

> 状态：设计定稿（待实施）
> 关联：`docs/设计总案.md`（总方案）、`docs/UI设计.md`（UI）、`docs/链路B-设计契约.md`（跨仓契约）、`TODO.md` P1
> 决策记录：2026-10-05 与用户确认（见 §4）

## 1. 背景与目标

**目标**

1. **批量合并**：菜单「制作书籍 → 批量合并丛书…」对所选丛书逐部执行 **合并 + ZIP 打包**，
   产出逐部报告，失败隔离、可取消、已完成保留。
2. **与官方更新协调**：官方 XML / 本地库更新后，丛书对应的**官方书自动重新下载**、
   **自制书自动重制**，再参与合并/ZIP。

**非目标（首版）**

- 批量不做校验：设置「制作书籍=校验」时，批量仍只普通合并（不生成+校验+导入）。
- 批量不做「导出」（复制目录）；后续可加。
- 来源在批量对话框内单选（官方书/自制书，初始值=右栏当前选择）；丛书 `source`/`work_sources`
  不参与分流，整批统一。

## 2. 现状与问题

| 链路 | 现有行为 | 问题 |
|---|---|---|
| 自制（xml） | `ensure_products(regen_all=False)` 仅缺；`sources_newer`（工作根 XML mtime > 产物）自动重制 | 已满足「XML 更新→重制」，无需改 |
| 官方 | 合并/ZIP/导出前置**只判文件是否存在**（`_merge` 6670-6690、`_zip` 7026-7054、`_export` 7222-7250）；右栏「下载/更新」`_download()` 全量 HEAD（zip 型无 HEAD 信息、总重下） | 无「XML/库更新 → 官方书重下」判据 |
| 版本 | `official_library.root`（如 `E:\CBETA\2026r2`）目录名带版本，无人读取；无任何备齐记录 | 换库版本无信号 |
| 批量 | 无入口；`_merge`/`_zip` 与 UI 深度耦合（弹框、进度窗、页签） | 无法复用 |

## 3. 设计

### 3.1 术语

- **备齐（prepare）**：合并/ZIP/导出前确保素材「存在且不过期」。
- **水位（watermark）**：某 `(work, fmt)` 上次备齐时看到的源 mtime + 本地库版本，
  记在 `config/official_state.json`。用于避免「源永远比产物新 → 每批重下」。

### 3.2 官方过期判据（定稿）

对 `(work, fmt)`：

1. 产物缺失（`official_ebook_source.local_path` 不存在）→ **过期**。
2. 有水位：`source_mtime(config, work) > 水位.src_mtime`
   **或** `水位.lib_version != library_version(config)` → **过期**。
3. 无水位（升级后首跑）：回退 `source_mtime > product_mtime`
   （目录型产物取目录内最新文件 mtime）；**不**触发版本判定（避免首跑全量重下）。

辅助定义：

- `library_version(config)` = `official_library.root` 的目录名（空 → `""`）。
- `source_mtime(config, work)` 复用 `xml2pdf_bridge.source_mtime`（工作根 `{work} {书名}/*.xml` 最新 mtime；无 → None）。
- `product_mtime(path)`：文件 → `st_mtime`；目录 → 递归文件最大 mtime；空目录 → 0。

**说明**：官方书是 CBETA 从官方 XML 产出，故「XML 文件变新」或「本地库换版本目录名」
都视为官方书过期。纯官方用户（本地无 XML）只靠 缺失 + 版本名 两个判据。

### 3.3 水位库 `config/official_state.json`

- 新模块 `cbeta_publish/books/official_state.py`（仿 `verify_cache.py`：原子写、损坏回空库、不抛）。
- 路径随 `_config_path` 隔离（测试临时目录自动生效）；`.gitignore` 忽略；`test_no_pollution.py` REAL_FILES 纳入。
- 结构（**按 (work, fmt) 粒度**，避免部分格式失败误标整部）：

```json
{
  "schema": 1,
  "works": {
    "T0001": {
      "pdf": {"src_mtime": 1759300000.0, "lib_version": "2026r2", "checked_at": "2026-10-05T12:00:00"}
    }
  }
}
```

- API：`state_path(config)` / `load` / `_save` / `get` / `mark_checked(config, work, fmt)` / `stale(config, work, fmt, dest_dir)`。
- 写入时机：该 `(work, fmt)` **下载成功或确认未变（DownloadWorker 跳过）** 后；失败不写（下次重试）。
- 版本判定按 `(work, fmt)` 记录：换库后成功的项更新版本，失败项保持旧版本 → 下次只重试失败项。

### 3.4 统一前置 `_prepare_official`（主窗口）

`_prepare_official(works, fmts, dest_dir, policy="stale") -> (src_map, failed)`

- `policy`：`missing`（仅缺）｜`stale`（缺/过期，**默认**）｜`all`（全部重下）。
- 生成 pairs → 复用 `_download_missing` 进度窗；`all` 时 `force=True`（跳过 HEAD 未变判断）。
- 下载后按 `_dl_stats["failed"]` 反推成功项 → `official_state.mark_checked`。
- 返回 `src_map = {fmt: {work: local_path}}` 与 failed 明细。
- **单部弹窗留在各流程 wrapper**（「是否先下载/更新」）；批量不弹、直接按策略执行。

### 3.5 批量流程

**入口**：菜单「制作书籍 → 批量处理…」→ `cbeta_publish/gui/batch_dialogs.py` 的
`BatchDialog(mode="combined")`，窗口内顶部单选切「更新素材 / 合并丛书」。
（**不新开一级菜单**；一级菜单仍为 设置/制作书籍/视图。）
对话框默认：操作=更新素材、来源=官方书。

**对话框字段**

- 丛书复选清单（默认全选非空；全选/全不选）；每行显示有效分册配置，可「配置…」设单书（含「跟随全局」）。
- ☑ 合并（取右栏已勾选的 pdf/epub；若无则禁用并提示）。
- ☑ ZIP 打包（格式沿用 `config.default_formats[来源]` ∩ `_pack_avail_fmts()`）。
- ☑ **合并前自动备齐（默认开）**：开=阶段一按策略更新素材（有水位，已更新则零成本）；
  关=只用现有素材，缺的记失败（适合「先批量更新素材，再合并」的两步流程）。
- ☑ **清除上次合并输出（默认关，仅合并模式）**：开=阶段零先删 `output_dir/{丛书名}/`
  （合并与 ZIP 都在内）并清除该丛书 `last_publish_at/dir`（JSON＋内存），执行前二次确认
  （列出目录；取消则整批不跑）；缺失记「无输出可清」；只动输出目录，不动素材库与 XML 源；
  逐部清除结果写入报告（`清除：…` 行），根下报告仍覆盖写。
- ☑ 报告落盘（默认开）→ `output_dir/批量合并报告.txt`。
- 官方刷新策略：**XML较新则重下（默认）** / 仅缺 / 全部重下。
- 自制策略：**仅缺（源新自动重制，默认）** / 全部重制。
- 来源：对话框内单选（官方书/自制书，默认官方），只显示对应策略；
  预设：右栏当前；合并与 ZIP 输出：`output_dir/{丛书名}/`。

**执行 `_batch_merge(...)`**

0. **阶段零 清除**（仅勾选时）：二次确认 → 逐部删输出目录＋清发布标记（见上）。
1. **阶段一 备齐**
   - 所需格式并集 = 合并格式（pdf/epub）∪ ZIP 格式。
   - 官方：所有选中丛书的「缺/过期」对合并为**一次** `_prepare_official`（一个进度窗）。
   - 自制：一次 `_ensure_xml_batch(所有 works, 格式并集)`（内部自动 `sources_newer` 重制）。
   - 备齐失败项记入对应丛书，阶段二跳过该 `(work, fmt)`。
2. **阶段二 逐部**
   - `_merge_one_coll`（若勾选合并）→ `_zip_one_coll`（若勾选 ZIP）。
   - 空白丛书名 → 该部 `skipped`（不弹命名框）。
   - 编辑说明有问题 → **合并**记失败跳过；ZIP 不依赖说明，照常执行。
   - `ask` 分册模式（全局或单书）不弹框：用 `merge.ask_last`；无记忆回退 `none`。
   - 失败隔离：单部失败不中断整批；取消即停（已完成保留）。完整状态机见 **§3.9**。
3. **收尾**
   - 进度窗总结（HTML 链接，可点开产物）+ 丛书信息页签逐部清单。
   - **有产物**的部照写 `last_publish_at/dir`（统一 `output_dir/{丛书名}/`）；
     失败/跳过/取消当前部不写（§3.9）。
   - 不切右栏选择、不弹 `_prompt_save_collection`。

**进度窗**：批量**单一窗口**贯穿（`_make_progress("批量合并", 总单元)`）；
`_merge_one_coll`/`_zip_one_coll` 接受 `update(percent,label,append)->bool` 适配器
（False=取消），批量适配器把步骤内百分比映射到总进度并加「丛书名」前缀。
单部调用时不传适配器 → 各流程自建进度窗（现状不变）。

### 3.6 丛书独立分册配置

- 丛书 JSON 新增可选 `merge: {mode, depth, name_template}`；**无此键 = 跟随全局**。
- `collection_model.normalize_collection`：读入规范化（mode 白名单、depth 1–5、template 字符串）；
  `Collection` 增字段；`to_dict` 仅在有自定义时输出该键。
- 主窗口 `_coll_merge_cfg(d)` → `(mode, depth, template)`（单书优先、缺省全局）。
- **编辑窗口重用合并时的分册窗口** `MergeDialog`（`allow_follow`/`allow_ask`）：
  顶部「跟随全局」（勾选时显示并禁用为**当前全局**模式/深度/模板），并含「合并时选择」；
  预览复用 `_merge_preview`。两个入口：
  1. 右栏书单按钮行、**「平铺」分组下拉框左边**的 `分册…`（对当前丛书）；
  2. 批量窗口点列表**「分册」列**任意一行。
- **确定即落盘**：`_save_coll_merge(key, merge)` 写/删 `d["merge"]`；非空白名立即
  `_save_one_collection`，空白名 `_mark_coll_changed`（暂存内存）。批量窗口取消不影响已保存。
- 清单「分册」列显示来源：`丛书：…` / `跟随全局：…`。
- 单部 `_merge`/`_zip` 也改用 `_coll_merge_cfg`（`ask` 单书配置在合并时用 `ask_last`）。

### 3.7 重构边界（行为保持）

- 从 `_merge` 抽出 `_merge_one_coll(...)`：无弹框、无页签切换、无保存提示；
  返回 `{"success":[...], "skipped":[...], "failed":[...], "cancelled":bool,
  "note_problems":[...], "out_dir":Path}`；**状态/归因由调用方**按 §3.9 计算。
  `_merge` 变薄 wrapper（保留空白名保存、`ask` 弹框、下载询问、编辑说明询问、收尾 UI）。
- 从 `_zip` 抽出 `_zip_one_coll(...)`：入参含 `src_map/out_dir/mode/depth/template/update`；
  无 `QFileDialog`、无格式选择、无备齐。`_zip` 变薄 wrapper。
- `_export` 不抽（首版批量不含导出），只把官方前置换成 `_prepare_official`。
- `_pack_group_works` / `_merge_basename` 支持**显式 template**（批量/单书模板）。
- `_tmp_preset` 的 `regen_all` 由调用方传入（单部：有临时预设=重制；批量：按自制策略）。

- 与进度窗总结、丛书信息页签清单一致（§3.9）。
- 逐部另有 `清除：…` 行（P5 阶段零）与 `缺素材：…` 行（本节；最多 20 条）。

### 3.9 失败与状态设计（定稿）

**每部最终状态**（取最差；取消优先标记）：

| 状态 | 含义 |
|---|---|
| `ok` | 所有勾选操作按计划完成，无失败/跳过 |
| `partial` | 有产物，但有 work/fmt 失败或跳过（缺书、备齐失败、某格式失败） |
| `failed` | 无任何产物（合并与 ZIP 都失败） |
| `skipped` | 未开始（空书/空白名/读丛书失败） |
| `cancelled` | 用户取消：当前部终止；后续未开始部也标 `cancelled` |

**失败归因阶段**：`prepare`（备齐）/ `merge` / `zip` / `io`（读丛书、写报告）。

**部内 `skipped` 名单**（区别于部状态 `skipped`）：`_merge_one_coll(skip_missing=True)`
缺素材的 `(work,fmt)` 进部内 `skipped`，批量结果透出（`r["skipped"]`），报告记
`缺素材：…` 行（20 条截断），页签显示前 3 部。全缺＋无产物时部状态为 `failed`
（附 `"{fmt} 无文件"`），此时页签不再是光秃秃的"产物 0"。

**`reason` 自动归因**（无 reason 且有缺失/失败时）：有缺失＋未勾「合并前自动备齐」→
"素材缺失：未勾选「合并前自动备齐」，请先跑「批量更新素材」或勾选后重试"；
有缺失＋已备齐→"备齐后仍有缺失（见报告明细）"。状态栏同步追加"有失败（见丛书信息页签/报告）"。

**各失败点行为**（除「取消」与「输出目录不可写」外，**任何单部失败都不中断整批**）：

| 失败点 | 行为 | 状态影响 |
|---|---|---|
| 读丛书 JSON 失败 | 跳过该部，继续 | `skipped`（原因入报告） |
| `work_ids` 为空 | 跳过 | `skipped` |
| 空白丛书名 | 跳过（**不弹命名框**） | `skipped` |
| 备齐某 `(work,fmt)` 失败 | 该对记失败；合并/ZIP 只处理可用对，其余照做 | 有产物 `partial`；全不可用 `failed` |
| 编辑说明有问题 | **合并**跳过并记失败；ZIP（若勾选）不依赖说明、照常执行 | 有 ZIP 产物 `partial`；否则 `failed` |
| 合并某格式异常/无可用书 | 该格式记失败，继续其它格式与后续丛书 | 有产物 `partial`；全失败 `failed` |
| ZIP 某格式/某组失败 | 记失败，继续其它格式与后续丛书 | 有产物 `partial`；全失败 `failed` |
| 部级未预期异常 | `try/except` 兜底记 `failed`，继续下一部 | `failed` |
| 输出目录不可写 | **开始前预检**：对话框提示并中止整批（不进入阶段一） | 批次中止 |
| 报告写入失败 | 弹框提示；进度窗总结照显；不改变部状态 | 不影响 |
| 用户取消（阶段一） | 不进入阶段二；报告写「已取消（备齐阶段）」+ 已完成备齐统计 | 未开始部 `cancelled` |
| 用户取消（阶段二） | 当前部立即停（已生成分册文件保留，但**不写 `last_publish`**）；后续部不再开始 | 当前部与后续部 `cancelled` |

**部分成功细节（与单部语义对齐）**：

- 合并：某 work 缺/备齐失败 → 跳过该 work、其余照合（同单部「否=跳过缺书继续」）；缺项入 `失败`。
- 某格式没有任何可用书 → 该格式记失败（现状 `_merge` 行为），继续下一格式。
- ZIP：某 work 缺 → 记失败，组内其余照打（现状 `_zip` 行为）。

**取消语义**：

- 取消后**始终写报告**（报告路径不可写除外）。
- 已完成部保留产物并写 `last_publish`；当前部半成品保留文件但不写 `last_publish`（避免半成品记为发布）。

**`last_publish`**：

- 仅当该部**有产物**（合并或 ZIP 成功）时写 `last_publish_at/dir`；统一写 `output_dir/{丛书名}/`。
- 完全失败/跳过/取消当前部不写（保留上次值）。
- `_commit_publish_meta` 不弹保存提示；丛书有未保存改动则并入脏状态（现状）。

**丛书信息页签**：每部带状态前缀；成功产物链接（合并/ZIP）＋缺素材前 3 部＋失败前 2 条＋
`原因`（自动归因，见上）；失败明细全文在报告与进度窗。

**进度窗总结**：逐部一行 `[状态] 丛书名：产物 N，失败 M`；成功产物 HTML 链接（可点开）；
失败明细列前若干条。**失败停留成功关**：有 `failed/partial` 或取消时调 `finish(总结行)`
停留手动关闭（报告先落盘，总结行带报告路径）；全 `ok` 仍直接关闭。

### 3.10 与单部流程的关系（隔离保证）

**共享行为（有意为之，非批量引入）**

- S3 的官方「缺/过期」前置（XML 源较新/库版本名变化则重下）是**单部与批量共同**的行为升级
  （用户决策 #4「统一升级」）。即：单部合并/ZIP/导出的前置提示会从「仅缺」变为「未下载/需更新」。
- S4 的丛书 `merge` 配置**单部也生效**（`_coll_merge_cfg`）：这是丛书自身的分册设置，
  在批量对话框里改它，等于改该丛书的配置，单部随后也会采用。若要「批量临时覆盖、不改单部」，
  需要另行设计（当前**不做**）。
- S5/S6 抽取 `_merge_one_coll`/`_zip_one_coll` 为**行为保持重构**，单部流程输出/交互不变，
  由现有 `test_download_log`/`test_pack_formats`/`test_pack_split`/`test_by_catalog` 护住。

**批量运行期不修改（隔离项）**

- 右栏来源/预设/格式勾选；`config/app.json`（不调用 `_save_config`）。
  （批量来源取对话框内单选，右栏只作初始值、不被修改。）
- `default_source`、`xml2pdf.preset`、`merge.ask_last`、`ui.layout`（批量不写这些全局状态；
  `ask` 模式只**读** `ask_last`）。
- 不弹 `_prompt_save_collection`、不切右栏丛书选择、不写 `config/ui_state.json` 的 `last_collection`。
- 不调用设置对话框、不改 `cover`/`xml2pdf` 等全局配置。

**批量会写（发布结果/用户显式设置，属预期）**

- `config/official_state.json`：官方备齐水位（全局，按 `(work, fmt)`）。
- 各丛书 JSON：仅成功部的 `last_publish_at/dir`；用户在批量对话框显式设置的丛书 `merge` 配置。
- `output_dir/`：合并/ZIP 产物与 `批量合并报告.txt`。

**并发**：批量与单部不并行（同一主线程/窗口、同一进度窗体系），无并发冲突；
批量结束后的当前视图刷新仅 `_load_coll_works()`（当前丛书显示），不改选择。

**测试保证（§7）**：批量用例断言运行前后右栏选择/全局 config 不变；
单部重构回归用例在 S5/S6 全绿。

### 3.11 批量更新素材（独立入口，与批量合并共用备齐）

**目的**：把「刷新素材」与「产出」分开走——先更新、检查结果，再（可选）批量合并；
批量合并的「自动备齐」因水位已记，此时几乎零耗时。

- 入口：菜单「制作书籍 → 批量处理…」→ `BatchDialog` 顶部选「更新素材」
  （与「合并丛书」同一窗口、同一入口；**§3.5**）。
- 字段：丛书复选（默认全选非空）；来源单选（官方书/自制书，默认官方）；
  官方策略（XML较新则重下/仅缺/全部重下，仅来源=官方时显示）；
  自制策略（仅缺/全部重制，仅来源=自制时显示）；来源=自制时另有一行灰字提示
  「CBETA XML 源由 xml2pdf 更新和维护，publish 只读不写」；☑ 报告落盘 → `output_dir/批量更新报告.txt`。
  无合并/ZIP 选项、无分册配置。
- 执行：只跑阶段一备齐（官方 `_prepare_official`；自制一次 `_ensure_xml_batch`），
  不合并、不写 `last_publish`、不碰 `output_dir` 产物（自制产物仍写工作根 `xml_books_dir`，属预期）。
- 报告：头部（时间/来源/预设/格式并集=合并默认格式 ∪ ZIP 默认格式/策略）+
  逐部 `ok|partial|failed|skipped` + 失败明细（§3.9 状态，无 `merge`/`zip` 归因）。
- 隔离同 §3.10：不改全局配置/右栏选择；只写 `official_state.json`、自制产物、报告。

## 4. 关键决策记录（用户确认）

1. **官方过期判据**：XML 源较新 + 本地库版本名变化（两者都覆盖）。
2. **批量官方默认刷新**：XML 较新则重下（避免每次全量）。
3. **批量 ZIP**：格式沿用 `default_formats`，输出到 `output_dir`。
4. **单部流程**：合并/ZIP/导出 统一升级为「官方源新则重下」。
5. **XML 更新方式**：CBETA XML 源由 xml2pdf 更新和维护，publish 只读不写
   （`materialize_work` 缺才下，无强制刷新口；`--update-data` 只管上游自带数据文件）；
   publish 侧仅在批量更新（自制）与设置页 XML 工作根行提示归属。本地库版本升级
   走 `official_library.root`（`E:\CBETA\2026r2`→新版目录名变化即触发官方重下）。
6. **更新与批量的关系**：**逻辑共用 + 入口分开**——共用 `_prepare_official`；
   新增「批量更新素材…」独立入口；批量合并保留「合并前自动备齐」开关（默认开，可关）。
7. **批量来源选择**：对话框内单选（官方书/自制书，初始值=右栏当前），只显示对应策略；
   右栏选择只作初始值、不被批量修改。

## 5. 边界与取舍（再审核）

- **首跑无水位**：回退「源 mtime > 产物 mtime」可能触发一次较多重下（zip 型真下载）；
  用户可选「仅缺」规避；水位建立后不再重复。
- **zip 型无 HEAD**：`remote_info` 对目录型返回 None，无法远端比对；靠水位 + 缺失控制。
  「全部重下」成本高，仅作显式选项。
- **本地库同大小跳过**：`copy_from_library` 对同大小目标幂等跳过 → `force=True` 必须绕过
  （否则换库但同大小文件不会更新）。需给 `copy_from_library`/`download_ebook`/`DownloadWorker`
  加 `force` 透传。
- **`verify_build` 开启**：批量仍普通合并（已冻结）；如需校验请单部操作或后续扩展。
- **来源全局**：批量不按丛书 `source`/`work_sources` 分流；来源整批统一，
  取对话框内单选（初始值=右栏当前）。
- **无本地 XML 的 work**：仅缺失 + 版本名判据，无源 mtime 判据。
- **进度窗**：批量单窗贯穿；单部保持各自窗口。
- **测试兼容**：`tests/test_download_log.py`、`tests/test_pack_formats.py` 中 monkeypatch
  `_download_missing` 的 lambda 签名需随 `force` 参数更新。
