# 供上游审核：首选基线缺失时，指纹判定与真校验回退口径不一致（非 T/X 藏经 pdf/docx 永不复用）

以下"实测"均为 publish 仓只读脚本测得（真实用户配置与库）。
结论若与上游实现不符请指正。

## 1. 现象（用户报告）

《藏要》第二辑等丛书里，K0016、K1482 第二次重制仍出现"生成并校验 K0016 …通过"
（即未复用）；而同一轮的其它书正常进"复用旧校验（跳过）"。

## 2. 定位（实测）

- **记录库**：K0016/K1482 都**只有 epub** 一条（fp-2，2026-10-14T20:00:06，
  inputs 为 `K05n0016.xml` / `K41n1482.xml`）；pdf、docx **无记录**。
- **现算指纹**（当前代码，只读复算）：
  - K0016：pdf = None、docx = None、epub = `verify-fp-2:sha256:caf1da28…`（与记录一致）
  - K1482：同上结构（pdf/docx = None，epub 有值）
- **基线发现**（`_official_superset`，两书同型）：
  - html 1 个（如 `K0016_001.html`，在工作目录）、txt_notes 1 个、epub 1 个
  - **docx 0 个**（本地库 `cbeta_docx_2026r2` 顶层仅 `T`、`X` 两个藏经）
- **格式链**：pdf → 生效格式 docx（engine docx2pdf）→ `['docx','html']`；
  docx → `['docx','html']`；epub → `['txt_notes','epub','html']`
- **真校验报告**（第二辑校验目录，K0016）：
  - `[K05n0016] 2 format: 1[pdf=2], 2[docx=OK(0/0)]`、`[--] pdf 已覆盖（已由 docx 校验）`
  - `docx→html 【源】…\K0016_001.html`、`→ html 通过：逐字完全一致`
  → 首选 docx 缺失时，真校验**回退 html** 比对并通过。
- **指纹侧**：`_verify_fingerprint_inner` 对 `official.get(chain[0])` 有硬性要求，
  缺失即返回 None（注释："实际跑会下载，本次不能证明"）→ pdf/docx 永久 None。
- **上游自述规则**：`pycbeta/fetch.py:12`——"docx/odt 目前官方仅大正藏 T 与
  《卍續藏》X 提供，其它藏经 404 时静默跳过"；`pycbeta/verify.py:2132-2141`
  （`verify_one`）：首选缺失 → `ensure_baselines` 按需下载（404 静默跳过）→
  重新发现 → `resolve_bases` 取链内首个可用种。

## 3. 结论

同一件事，两处口径不一致：

| 环节 | 首选（docx）缺失且不可下载时 |
|---|---|
| 真校验（`verify_one`） | 下载尝试 404 → 回退 html → 给出通过/失败结论 |
| 指纹（`_verify_fingerprint_inner`） | 直接 None（"不能证明"）→ 不记库 → 每轮重验、永不复用 |

影响面：**所有非 T/X 藏经**（K、J、A、B、C、CC…）在 **pdf 与 docx** 两格式上
永不记库/复用；epub 因链首是 txt_notes（各藏经均有）不受影响。
（publish 侧无法代偿：记录必须携带指纹值，伪造无意义；只能请上游对齐。）

## 4. 建议修法（上游）

把"首选缺失"的判定与真跑对齐：

1. 若 `chain[0]` 属于"官方仅 T/X 提供"的种（docx/odt，见 `fetch.py:12`）且本书
   藏经（`parse_work_id(work_id)[0]`）非 T/X：真跑必然 404 并回退 →
   指纹**按 `resolve_bases` 的回退结果证明**（payload 的 `baselines` 即回退种，
   与真跑同口径）。
2. 其它情况保持 None（首选可能下载成功，本次不能证明）。
3. 回退结果也为空（`resolve_bases` 返回空）→ 仍 None。
4. 建议把"仅 T/X 提供"的种与藏经判定抽成 `fetch` 与 `verify` 共用的常量/函数
   （避免两处知识漂移）；该规则已在 `fetch.py:12` 与 `fetch.py:983` 出现过两次。

**安全性说明**：若之后首选种出现（人工放置或官方开始提供），`chain[0]` 存在 →
指纹切回首选口径 → 旧（回退口径）记录失效 → 自动重验。方向安全。

## 5. 验证建议

- 单测：
  - 非 T/X 且 docx 缺失、html 可用 → 指纹非 None，且 payload `baselines` 为 html；
  - T/X 且 docx 缺失 → 仍 None（下载可能成功）；
  - 首选与回退都缺失 → None；
  - 回退口径与真跑 `resolve_bases` 结果一致（集合与顺序）。
- 实机：K0016/K1482 复算指纹非 None；重制第二轮两书进"复用旧校验（跳过）"。
